# 서무 문서 근거 답변: 모델 교체와 검증

업무 흐름(`backend/app/assistant.py`)은 근거 검색·프롬프트·추출 근거 대체 응답을 담당합니다. 공급자 전송(`model_provider.py`)은 요청·응답 해석만 담당하며 `ModelProvider` 계약으로 교체할 수 있습니다. 모든 공급자의 답변은 `answer_validation.py`의 동일한 비어 있음·길이·인용 식별자 검사를 통과해야 합니다. 인용 식별자 통과는 내용 전체의 사실성을 증명하지 않습니다.

기존 OpenAI 호환 엔드포인트는 `SEOMU_LLM_BASE_URL`, `SEOMU_LLM_MODEL`, 필요할 때 `SEOMU_LLM_API_KEY`로 지정합니다. 키는 서버의 비밀 설정으로 전달하며 소스·결과 기록·채팅에 넣지 않습니다. URL은 `/chat/completions` 이전 기반 주소입니다. 호환되지 않는 공급자는 `generate(messages) -> ModelResult` 어댑터를 추가하고 동일한 검증을 적용합니다. 모델을 바꾼 뒤 서버를 재시작합니다.

정상 AI 응답에는 기존 필드에 더하여 `model_run`이 포함됩니다. 공급자 유형, 요청한 모델 식별자, 요청 소요 밀리초, 인용 검증 상태만 포함하며 주소·키·공급자 오류 본문은 노출하지 않습니다. 실패하면 원문 근거로 전환하고 성공 메타데이터를 만들지 않습니다. 서버에서 설정한 모델 식별자는 공급자의 실제 내부 모델 정체까지 증명하지 않습니다.

## 합성 검증 재현

개발 의존성이 설치된 Python에서 `backend` 폴더로 이동하여 `python -m pytest tests/test_ai_boundary.py -q`를 실행합니다. 테스트는 합성 교육 문서와 HTTP 모의 응답만 사용합니다. 실제 모델 호출이나 2종 모델 입증으로 계산하지 않습니다.

Windows에서는 실행 전 `$env:PYTHONUTF8='1'`을 지정합니다. 기존 문서 인식 하위 프로세스의 UTF-8 출력이 시스템 CP949 인코딩으로 해석되는 문제를 피합니다. 이번 검증은 격리 환경의 pytest 9.1.1, httpx 0.28.1, defusedxml 0.7.1, Pillow 12.3.0으로 경계 테스트 10개를 통과했습니다.

## 두 모델 실호출 입증 절차

1. 실제 사용 권한이 있는 서로 다른 두 모델을 선정합니다. 공통기반 후보 이름만으로 사용 가능 상태를 가정하지 않습니다.
2. 개인정보 없는 동일한 합성 교육 문서를 문서 서버에 등록하고 같은 질문 `교육 제출기한`으로 요청합니다.
3. 첫 모델의 서버 설정으로 근거 검색→생성 답변→원문 인용 확인을 실행합니다. 모델·버전 식별, 실행시각, 입력 자료 해시, 응답의 `model_run`, 성공/실패와 사람의 사실 확인 결과를 기록합니다.
4. 두 번째 모델로 설정을 교체하고 서버 재시작 후 같은 자료와 질문으로 반복합니다. URL과 키는 증거 기록에서 제외합니다.
5. 각 모델이 모두 AI 모드로 실행되고 인용 원문과 주요 기능이 정상인지 확인한 뒤에만 두 모델 완주로 기록합니다. 추출 근거로 전환된 실행은 AI 완주가 아닙니다.

현재 범위: 연결 구조 및 모의 검증. 두 모델 실호출·완주는 별도 증거가 필요한 미확인 상태입니다. 브라우저 정산 문서 초안은 현재 계산·입력 기반 기능이며 이 모델 호출 경계의 실호출로 증명되지 않습니다.
