# 상황별 서무비서 — 구현·사용·검증 안내

2026.10.19 / 세션2 지정과제 ② 서무비서 개선

## 실제 구현한 흐름

1. 관리자가 기관 규정·지침을 가져온다. TXT·MD·HWPX·붙여넣기는 브라우저에서 직접, PDF·HWP·이미지 등은 기존 문서함에서 인식 후 `이 규정으로 업무 절차 만들기`로 연결한다.
2. 연결된 모델로 절차 초안을 만든다. 처리 순서·필요 서류·기한·조건 질문·원문 인용을 편집한 뒤 저장한다.
3. 직원은 `상황별 업무 도우미`에서 기관 절차를 선택하고 상황을 말한다. 직원 명단·자료요청 생성이 선행 조건이 아니다.
4. 모델을 선택하면 상황에 명시된 조건만 추출한다. AI 미연결이면 등록된 명시 문구와의 일치를 표시하거나 필요한 조건을 직접 묻는다. 이 경우 AI 분석으로 표시하지 않는다.
5. 적용되는 단계와 다음 할 일을 보여준다. 답이 없는 조건부 단계는 확인 대기로 남긴다. 제외된 단계도 이유를 볼 수 있다.
6. 상황·조건·처리순서·근거가 포함된 편집 가능한 XLSX 업무준비서를 저장하거나, 기관 서식에 값을 채운다.
7. 업무건을 이어서 처리한다. 규정이 바뀌면 문서 출력을 막고 변경 내용을 확인한다. 확인 후 동일한 단계의 처리 기록을 유지하고 달라진 단계는 다시 확인한다.

## 최소한의 체험

처음 화면 → `상황 말하고 시작` → `출장 정산` 합성 체험.

입력 상황: `현장점검 출장을 다녀왔어요. 공용차를 탔고 점심을 제공받았어요. 정산을 준비해 주세요.`

- 공용차·식사 제공 두 답을 명시 문구 일치로 가져온다. 이는 생성형 AI 호출이 아니다.
- 개인 교통수단 영수증 단계는 제외하고, 차량 이용내역·식사 제공 내역 확인 단계가 남는다.
- 모르는 조건이 없는 경우 같은 질문을 다시 하지 않는다.
- `업무준비서 XLSX 저장`에서 근거와 처리순서를 확인한다.
- `연습 서식 바로 적용` → 담당자만 입력 → `기관 서식 초안 저장`. 기관 원본 서식은 파일 선택으로 한 번 등록해 재사용한다.

두 번째 체험: `물품 구매·검수` → 납품 후 검수 전 조건에서 검수조서 준비를 확인한다. 검수 완료·지급 전으로 답을 바꾸면 지급 서류 준비 단계로 달라진다.

두 자료는 합성 연습 지침이다. 출장 종료 후 5일 등의 숫자는 실제 기관 규정·법정 기한이 아니다.

## 기관 관리자가 한 번 준비할 것

- 현행 규정·지침·서식, 적용 기관, 시행일 또는 문서 버전.
- AI 초안의 조건과 누락을 검토하고 필요한 경우 수정. 단순한 연속 원문 인용 검증은 의미의 정확성을 보장하지 않는다.
- 복수 조건이 얽힌 규정은 단일 선택 조건으로 잘못 축약하지 말고, 조건 확인 단계로 남긴다. 현재 단계 조건은 질문 하나의 선택지 하나와 연결한다.
- 모델 연결과 문서 서버 접근 키. 기존 Gemma/GPT/OpenAI 호환 제공자 설정을 그대로 사용한다. 모델별 실제 동작 검증이 별도로 필요하다.

AI 없이 `원문 문단 나누기`도 가능하다. 이는 자동 절차 판단이 아니라 원문을 편집할 출발점을 만드는 기능이다.

## 기관 HWPX·XLSX 서식

원본 서식을 복사해 채울 칸에 `{{기관명}}`, `{{업무명}}`, `{{담당자}}`처럼 표시한 후 등록한다. 이 준비는 기관별 서식마다 한 번 필요하다. 빈칸의 의미를 자동 추론하거나 임의 위치를 덮어쓰지 않는다.

자동으로 가져오는 항목:

| 입력 표시 | 값 |
|---|---|
| `{{기관명}}` | 현재 절차의 기관 |
| `{{업무명}}` | 절차 이름 |
| `{{업무상황}}` | 해당 업무건의 상황 |
| `{{근거문서}}`, `{{규정버전}}` | 현재 절차의 출처·버전 |
| `{{처리순서}}`, `{{필요서류}}` | 현재 답에 적용되는 단계·서류 |
| `{{작성일}}` | 출력 당일의 기기 날짜 |
| 그 외 `{{담당자}}`, `{{출장일자}}` 등 | 비어 있는 항목만 직원이 입력 |

자동 항목은 별도 입력값으로 덮어쓰지 않는다. 절차·조건이 달라지면 현재 값으로 다시 계산한다. 다른 항목은 해당 업무건에서 재사용한다.

- 파일당 8MB, 압축 해제 합계 32MB, 절차당 서식 최대 10개.
- HWPX 본문 문단의 텍스트 표시와 XLSX 문자열·서식 있는 문자열의 표시를 채운다. HWP 구형 파일·암호 문서·XLSX 수식 셀의 표시·HWPX 도형 속 글자 등은 지원 범위 밖이다.
- HWPX의 여러 줄 입력은 `/`로 연결한다. 기존 스타일·본문 외 파일을 보존하며 오래된 미리보기는 제거하고 스크립트 내용은 비운다. 출력 후 한컴 프로그램에서 줄바꿈·표 높이 등을 확인해야 한다.
- XLSX는 기존 셀 서식·병합·수식을 유지하고 입력 문자열을 수식으로 변환하지 않는다. 매크로·외부 연결·포함 개체가 있는 파일은 거절한다.
- 원본 파일을 덮어쓰지 않는다. 출력명에는 `-초안`을 붙인다.

## 저장과 이관

- 기관 절차는 기존 `seomu-procedures-v1`, 업무건은 `seomu-situation-cases-v1`에 별도 저장한다. 현재 브라우저 단위이며 다중 사용자 공유 시스템이 아니다.
- 상황별 업무건은 최대 20개. 상황·조건 답·서식 입력값·처리 기록과 당시 근거를 보관한다. 평문 백업에는 업무 내용이 포함된다.
- 서식 원본은 IndexedDB에 보관한다. 기관 절차 묶음·업무건 백업에 서식 바이너리는 포함하지 않으므로 다른 기기로 옮길 때 원본 서식도 다시 등록한다.
- 기관 절차 이관 시 이전 서버의 문서 ID 연결은 해제한다. 출처·버전·원문은 유지하며 받는 기관 자료와 대조한다.
- 문서함에서 가져온 원문은 서버 연결 시 버전이 달라졌는지 확인한다. 최신 버전을 확인하지 못하면 이를 표시하고 저장된 버전으로 준비한다. 변경이 확인되면 갱신 전 출력을 막는다.
- 저장 실패를 성공으로 표시하지 않는다. 현재 화면 작업과 백업은 유지하며, 손상된 저장값은 자동 덮어쓰기하지 않는다.

## API와 제공자 경계

인증은 기존 `X-Seomu-Key`와 기관 단일 문서 서버를 사용한다.

- `POST /api/procedures/draft`: 원문 최대 24,000자·출처·버전·기관·제공자. 기한·서식명이 발췌에 존재하는지, 원문 인용과 조건 참조가 유효한지 검사한다. 절차·업무를 자동 저장하지 않는다.
- `POST /api/procedures/situation`: 상황·조건 질문·제공자. 알려진 선택지만 반환하며 상황에 존재하는 인용을 요구한다. 최종 단계 적용은 검토한 절차 조건을 사용한다.
- 실패 시 다른 제공자로 자동 전송하지 않는다. 서버 오류 본문·키·원문을 오류 응답에 노출하지 않는다.
- 사용자 상황·규정 속 명령을 실행하거나 외부자료를 조회하는 도구를 모델에 제공하지 않는다.

## 확인한 것과 남은 것

자동 검사 범위:

- 출장·구매 조건 분기, 미확인 조건을 대기로 유지, 반복 질문 감소, 업무건 복원.
- 근거 변경 시 출력 차단, 재확인 후 동일한 단계만 완료 유지, 다른 기관에서 완료 초기화.
- 손상된 업무건·잘못된 조건·선택지·중복 ID·크기 제한 검사.
- 서버 없는 HWPX 규정 읽기, 구성 파일의 구역 순서와 중첩 표 문단 처리.
- 실제 XLSX 압축 파일의 값·병합·서식·수식 보존과 HWPX XML의 나뉜 입력 표시·이스케이프·비압축 첫 mimetype·미리보기/스크립트 처리.
- 인증·제공자별 호출 경계·근거 없는 AI 제안 거절. 모델 응답은 합성 스텁을 사용한 계약 검사다.

별도 실증이 필요한 것:

- 실제 AI 두 모델의 같은 업무 처리 정확도와 응답시간.
- 다양한 기관의 실제 HWPX를 한컴 프로그램에서 열어 보는 호환성 확인.
- 실제 서무가 초기 설정·검토·보완까지 포함해 절감하는 전체 작업시간.
- 기관이 승인한 환경에서의 실제 운영·권한·보관 정책.

현재 기능을 95점 달성·시간 절감 달성 실적으로 표시하지 않는다. 지정과제 핵심 흐름을 구현하고 이를 실증할 수 있는 상태로 개선한 것이다.
